# 桌宠节奏师 · 画手素材替换与制作规范说明

本文档面向插画师 / 美术合作画手与桌面端测试人员，详细说明「**桌宠节奏师**」二次元桌前人物的分层结构、导出规范、替换方式及动效能力边界。全部分层字段与项目实际配置 `public/character_assets/manifest.json` 及人物渲染组件 `src/character/DeskCharacterScene.tsx` 保持严格一致。

## 本次版本新增：配置式表情

桌宠窗口现在始终透明，不再显示 `scene_bg.png`。原图可以保留，但不再加载和绘制。分层静态素材规范仍适用；新的整体动画允许使用透明 GIF、动画 WebP 或 APNG。

在 `character_assets/expressions.json` 的 `expressions` 数组中新增配置，即可在情绪页自动出现按钮，无需修改代码。点击「重载素材」生效。

```json
{
  "id": "sparkle",
  "name": "闪亮",
  "type": "accessory",
  "resources": { "overlay": "fx_love_hearts.png" },
  "durationMs": 4000,
  "random": true
}
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识，小写英文字母开头，后续可含数字、下划线和连字符 |
| `name` | 界面显示的中文名称 |
| `type` | `base` 为整体待机表情；`accessory` 为配件／局部表情 |
| `resources.animation` | 整体动画时替换主体全部图层；配件动画时作为透明叠加层 |
| `resources.eyes` / `mouth` | 分层表情路径，按互斥图层更换五官，避免重影 |
| `resources.overlay` | 透明配件路径，保留当前基础表情并随头部运动 |
| `durationMs` | 随机播放持续毫秒数，范围 100～600000；手动选择保持至下一次选择 |
| `random` | 是否参与随机抽取 |
| `event` | 可选，关联 `doze`、`think`、`shock`、`love`，继承状态页情境开关；打瞌睡请配置 `doze` |

必须保留 `id: neutral` 的自然基础表情。基础表情至少配置完整的 `eyes` + `mouth`，或一个 `animation`。配件至少有一种资源。资源必须位于素材目录内，不能使用上级目录或外部网络地址。画布与透明背景须统一。

整体动画文件自带五官，因此叠加配件时请使用 `overlay` 或配件 `animation`；眼嘴局部替换适用于原有分层主体。整体动画文件不能包含不透明背景，否则图片自身会遮挡桌面。

旧素材包缺少 `expressions.json` 时会从原 `manifest.json` 的表情与事件字段生成兼容配置。配置写错时显示中文错误并保留上一次成功加载的素材。

## 二、图片格式、画布尺寸与导出规范

为保证客户端直接加载而不发生缩放偏差、边缘白边或五官错位，所有素材必须严格遵循以下输出标准：

1. **图片格式**：**32-bit RGBA PNG**（即每通道 8-bit 的 RGB + 完整 8-bit Alpha 半透明通道，PNG `colorType = 6`）。请勿导出为 24-bit 无透明通道 PNG、JPG 或 WebP。
2. **画布尺寸**：严格统一为 **`800 × 800` 像素**（须与 `manifest.json` 中的 `"canvasWidth": 800, "canvasHeight": 800` 一致）。
3. **DPI 分辨率说明**：Electron / Chromium 网页渲染管线完全按**像素宽高（800 × 800 px）**进行绘制与定位。导出软件（如 SAI、CSP、Photoshop、Procreate）中的 `72 DPI`、`96 DPI` 或 `300 DPI` 仅影响印刷元数据，不影响桌面端显示大小，**只需确保导出文件的实际像素分辨率为 `800 × 800`** 即可。
4. **透明背景**：除 `scene_bg.png` 外，其余 **31 张**图层均必须保留完全透明背景，周围不得残留白边、网格底或纯色背景。
5. **全画幅 `(0, 0)` 统一对齐导出（严禁裁切紧边框！）**：
   - 程序内采用全画幅叠层定位（每张图片以 `inset-0 h-full w-full object-contain` 贴满同一 `800 × 800` 舞台容器）。
   - **切勿勾选“裁切透明区域 / Trim Transparent Pixels / 仅导出图层最小范围”**！即使是一双只有 `200 × 90` 有效像素的眼睛或一颗头顶小心心，也必须放在整张 `800 × 800` 画布的正确坐标位置上，从 `(0, 0)` 到 `(800, 800)` 完整导出。
6. **命名规范**：
   - 严格使用**小写英文字母 + 数字 + 下划线**（`snake_case`），扩展名一律小写 `.png`（例如 `eyes_happy.png`）。
   - **严禁包含中文文件名、空格、特殊符号或大小写混写**，以免在跨平台或自定义资源协议（`pet-asset://`）加载时出现编码歧义。

## 三、图层 Z 轴遮挡关系、支点坐标与运动分组

### 3.1 完整图层 Z 轴顺序（从底到顶）

程序在 `src/character/DeskCharacterScene.tsx` 中按如下严格顺序自底向顶叠放图层：

```text
[底层 Z1]  scene_bg.png                  （固定不动；showSceneBg=false 时隐藏）
    │      └─ <程序绘制> 节拍脉冲光环 beatRingRef
[Z2]       chair_back.png                （固定不动；椅背）
[Z3]       body_base.png                 （坐姿锚定；仅带极微弱呼吸缩放与反冲微动）
[Z4]       headRig 头部绑定组容器 ──────── 【整组随节拍同步点头、旋转与脉冲缩放】
             ├─ Z4-1: hair_back.png      （后发与双马尾）
             ├─ Z4-2: head_base.png      （纯净脸底图与耳朵）
             ├─ Z4-3: blush_base.png     （腮红）
             ├─ Z4-4: eyes_*.png         （唯一 1 张当前眼睛图：事件 > 眨眼 > 情绪）
             ├─ Z4-5: mouth_*.png        （唯一 1 张当前嘴巴图：事件 > 情绪）
             ├─ Z4-6: hair_front.png     （前发刘海与发饰，压在眼眉之上）
             ├─ Z4-7: head_headphones.png（耳机；仅 musicRunning && showMusicHeadphones 时渲染）
             └─ Z4-8: fx_*.png           （随机事件特效；附带轻柔上下浮动）
[Z5]       desk_surface.png              （固定不动；书桌面板，遮挡身体下半截）
[Z6]       prop_computer_off/on.png      （固定不动；chill 显示 off，study 显示 on）
[Z7]       prop_books.png                （固定不动；右侧书堆与笔筒）
[Z8]       prop_timer_clock.png          （位置固定；timerActive=true 时显示并带发光脉冲）
[Z9]       arms_chill.png / arms_study.png（固定不动；随模式二选一，压在书桌与部分道具前景）
    │      └─ <程序绘制> 节拍音符粒子（♪ ♫ ♩ ♬ ✦）
[顶层]
```

### 3.2 头部支点 `headPivot` 与颈部防露缝规则

- **支点坐标**：`manifest.json` 中默认定义 `"headPivot": { "x": 400, "y": 452 }`。
  - 程序将其换算为 CSS `transformOrigin` 百分比：`(400 / 800) * 100% = 50%`、`(452 / 800) * 100% = 56.5%`。
  - 每次节拍触发时，整个 `headRig` 容器以 `(400, 452)` 为旋转与缩放轴心，执行 `translate3d(0, finalHeadY, 0) rotate(finalHeadRot) scale(headScaleX, headScaleY)`。
- **脖子至少预留 30px 重叠区（防点头露缝 / 防断脖）**：
  - 在默认素材中，`head_base.png` 的下巴最低点位于 `y ≈ 448`（支点 `y = 452`）。
  - 因此 `body_base.png` 的脖子必须**在 `y = 412 ~ 470` 区间向上充分延伸并隐藏在下巴背后**（默认工程实际画到了 `y = 406 ~ 478`，比下巴高出约 **42px**，严格满足“向上预留至少 **30px** 重叠区”的要求），同时在颈部上方绘制柔和的下巴投影。
  - 这样当人物在重拍下大幅度向下点头、回弹上抬或微幅左右歪头时，头部与颈部衔接处**绝不会露出透明缝隙**。

### 3.3 “固定不动图层”与“跟随节拍运动图层”划分

- **固定不动图层（桌面及静态背景）**：`scene_bg.png`、`chair_back.png`、`desk_surface.png`、`prop_computer_off.png`、`prop_computer_on.png`、`prop_books.png`、`prop_timer_clock.png`（仅位置固定，亮起时有光晕）、`arms_chill.png`、`arms_study.png`。（注：`body_base.png` 整体保持坐姿锚定在桌面后方，仅由程序附带微幅呼吸缩放与头部反冲呼应。）
- **跟随节拍同步点头运动图层**：**整个 `headRig` 绑定组内的全部图层**（`hair_back.png`、`head_base.png`、`blush_base.png`、当前 `eyes_*.png`、当前 `mouth_*.png`、`hair_front.png`、`head_headphones.png`、当前 `fx_*.png`）。因为全部置于同一 DOM 变换容器 `headRigRef` 内，故点头、晃动、缩放时五官、发型、耳机与头顶特效 **100% 同步运动，绝对零漂移、零分离**。

## 四、重点详解：`head_base.png` 与五官图层的互斥分工原则

为彻底杜绝桌面人物常见的**“四道眉毛、双眼叠影、两张嘴”**问题，画手在拆分层时必须严格遵守以下两项铁律：

### 4.1 为什么 `head_base.png` 必须是“无眉毛、无眼睛、无嘴巴”的纯净脸底图？

- `head_base.png` 在程序运行期间**始终处于底层常驻显示状态**。
- 如果你在 `head_base.png` 上画了基础眉毛、睁眼底线或默认微笑线：
  - 当人物触发**眨眼**（切换到 `eyes_blink.png`）、**悲伤**（切换到垂眉 `eyes_sad.png` + 委屈 `mouth_sad.png`）或**震惊**（切换到挑眉 `eyes_shock.png` + O 型 `mouth_shock.png`）时，底图上的原五官不会被遮盖，直接透出形成“双眉/双眼/双嘴”穿帮！
- 因此，**`head_base.png` 只能包含**：脸部外轮廓线稿、双耳、肤色与立体赛璐璐阴影（刘海投影、下颌阴影、面颊过渡色）以及极浅的鼻子光影点；**禁止出现任何眉毛、睫毛、眼珠、眼眶或嘴部线条**。

### 4.2 程序互斥切换机制（同帧唯一 1 张眼 + 唯一 1 张嘴）

程序在 `src/character/DeskCharacterScene.tsx` 中通过确定性优先级计算五官槽位，确保任意时刻画面上**永远只有 1 张 `eyes_*` 和 1 张 `mouth_*`**：

1. **眼睛互斥槽（`layer-eyes`）计算顺序**：
   - **第一优先级（随机事件）**：若当前正在播放随机事件（`doze` / `think` / `shock` / `love`），直接加载 `randomEvents[event].eyes`；
   - **第二优先级（自然眨眼）**：若未触发随机事件，且处于约 150ms 的眨眼周期（`isBlinking === true`，注：`happy` 情绪下会自动抑制眨眼），直接将眼睛图**替换**为 `manifest.blinkEyes`（即 `eyes_blink.png`），不会在睁眼上“叠一层闭眼”；
   - **第三优先级（常驻情绪）**：否则加载当前情绪对应的 `expressions[emotion].eyes`（`neutral` / `happy` / `sad`）。
2. **嘴巴互斥槽（`layer-mouth`）计算顺序**：
   - **第一优先级（随机事件）**：若存在 `activeEvent`，直接加载 `randomEvents[event].mouth`；
   - **第二优先级（常驻情绪）**：否则加载 `expressions[emotion].mouth`。

> **画手绘制提示**：由于眨眼与情绪切换均会整张替换 `eyes_*.png`，请把**眉毛**和**眼睛**画在同一个 `eyes_*.png` 图层中（不要单独建眉毛层，也不要把眉毛画在 `head_base.png` 或 `hair_front.png` 上），这样开心、难过、惊讶、打瞌睡时的眉眼联动才是最自然的二次元神态。

### 5.3 自定义参数与文件名调整方法

- **更换自定义文件名**：只需保持文件名全小写加下划线且存在于同级目录，并将 `manifest.json` 对应字段值改掉即可，无需改动一行代码。
- **微调头部旋转支点 `headPivot`**：如果新立绘人物身形偏矮或偏高，在画图软件里测量“新角色下巴根部与脖子交接中心点”的像素坐标 `(X, Y)`，填入 `"headPivot": { "x": X, "y": Y }` 即可。
- **微调点头幅度与歪头角度**：
  - `nodAmplitudeScale`（默认 `1.0`）：控制随音乐上下点头位移倍率。若人物头顶发饰、呆毛或兽耳靠近画布上边界，建议适当调小至 `0.75 ~ 0.85` 防止切边。
  - `nodTiltScale`（默认 `1.0`）：控制随节拍左右倾斜晃动的角度倍率，可按角色性格调至 `0.6 ~ 1.3`。
- **背景与耳机显隐开关**：
  - `"showSceneBg": false` 可隐藏 `scene_bg.png`，呈现纯净桌面与角色轮廓；
  - `"showMusicHeadphones": false` 可在听歌时不叠加外置耳机（例如画手人物本身已佩戴头饰/不想遮挡发型时）。

## 六、两种运行场景下的替换与热重载流程

程序已内置完整的外部素材协议加载器（`electron/main.cjs` 中的 `pet-asset://` 协议 + `Cache-Control: no-store`）与资源版本号刷新机制（`src/character/assetLoader.ts`），区分以下两种场景操作：

### 场景 (a)：源码开发模式

1. 直接将新绘制的 PNG 文件覆盖放入项目工程目录：
   `public/character_assets/`（如有需要，同步修改该目录下的 `manifest.json`）。
2. 如果软件正在运行（`npm run dev:vite` + `npm start` 或浏览器预览），只需点击软件界面右上角的 **`🔄 重载素材`** 按钮即可立即刷新显示，**无需重启程序，无需重新执行 `npm run build` 编译**！

### 场景 (b)：打包后的 Windows Electron 分享版（推荐画手验收使用）

1. 解压分享包后，打开软件根目录下的 **`桌宠节奏师/character_assets/`** 文件夹（该文件夹与 `桌宠节奏师.exe` 位于同一级目录）。
2. 直接用你的新图覆盖该文件夹下的同名 PNG 文件（或修改该目录下的 `manifest.json` 参数）。
   > **底层原理**：打包态 Electron 主进程会自动**优先读取** `桌宠节奏师/character_assets/` 中的外部文件；只有当某个文件不存在时，才会回退读取内置包里的默认素材。
3. 在运行中的软件界面点击右上角 **`🔄 重载素材`** 按钮（或直接重启 `桌宠节奏师.exe`），新画的人物就会立即生效。**全程无需重新打包 `app.asar`，也无需安装 Node.js 或任何开发工具！**

## 七、当前动画能力与后续逐帧扩展边界说明

为了让美术合作方在创作前对最终动态效果有准确预期，以下客观区分**当前程序已支持的效果**与**需后续扩展序列帧的复杂动作**：

### 7.1 当前刚体变换 + 图层切换可实现的效果

- **节拍锁定弹簧点头**：基于冻结音频核心 `m1` 余弦节拍窗与弹簧阻尼物理，在每个音乐强拍精准下点头并自然回弹。
- **微幅左右摇摆与倾斜**：随节奏强度产生轻微 `rotate` 歪头倾斜与 `swayX` 晃动。
- **待机呼吸与微反冲**：无音乐时人物头部与身体保持柔和的呼吸上下浮动；点头时身体产生轻微反向缓冲。
- **自然眨眼**：每 2.4s ~ 5.2s 自动触发一次约 150ms 的 `eyes_blink.png` 眨眼替换（在 `happy` / `love` / `doze` 状态自动跳过）。
- **情绪与随机事件五官联动**：实时切换 `neutral` / `happy` / `sad` 表情与 `doze` / `think` / `shock` / `love` 随机动作，头顶事件特效（小心心、Zzz、思考气泡、震惊线）伴随轻柔悬浮动画（注：音乐播放期间自动禁止 `doze` 打瞌睡）。
- **音符粒子与场景道具联动**：跟拍时头顶飘出彩色音符粒子（`♪ ♫ ♩ ♬ ✦`）与扩散光环；自习模式下笔记本亮屏、桌面手臂切换为握笔写字、计时器开启后出现呼吸发光闹钟。

### 7.2 需要画手提供额外序列帧并扩展程序动画器的复杂动作

以下动作无法仅靠单张静态图层刚体平移/旋转实现，若后续版本需要支持，需美术方提供多帧序列图（Sprite Sheet 或序列 PNG），并由程序端扩展帧动画播放器：

- **大幅度 3D 转头与侧脸透视变化**：例如从正脸流畅转向 45° 侧脸或俯仰大透视变形。
- **手臂连续敲键盘 / 写字 / 翻书动画**：目前 `arms_study.png` 与 `arms_chill.png` 为固定姿态单图，连续打字或翻页需要至少 3~6 帧手部动作序列帧。
- **飘逸长发丝或衣带物理飘动**：目前 `hair_back.png` / `hair_front.png` 作为整体刚体随 `headRig` 一同运动，长发发梢的波浪形逐帧摆动需额外序列帧或骨骼网格变形支持。
- **连续口型（Lip-sync）**：目前嘴巴为情绪/事件互斥单帧切换，如未来加入语音互动张嘴说话，需要补充 `a / i / u / e / o` 等多档位口型图层。
