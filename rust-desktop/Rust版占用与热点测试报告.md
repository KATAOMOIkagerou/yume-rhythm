# Rust 版当前占用与热点测试报告

测试日期：2026-11-20；版本：当前透明修正版发布程序。正常启动复核：2026-11-20T11:43:48.826Z 至 2026-11-20T11:44:23.828Z（UTC）。

## 结论

当前版本存在明确的性能优化空间，**第一优先级是透明区域命中掩码的全画布读回与重复构建**。正常启动、不开调试端口时，整个应用进程树平均 CPU 为 **4.94%**，独占驻留内存 **419.6 MiB**，提交内存 **483.5 MiB**。Rust 主进程本身平均 CPU 为 1.90%、独占驻留 4.4 MiB；主要内存在 WebView2 子进程。

同一实例 A/B/A 对照中，临时停用掩码更新、保留角色动画，CPU 从两次正常段平均 **2.35%** 降至 **1.34%**，下降 **42.8%**。这是定位实验，停止掩码会破坏随动画更新的精准穿透，不能作为可直接交付的优化方案。

## 1. 环境与统计口径

- 处理器：12th Gen Intel(R) Core(TM) i7-12700H；操作系统向进程暴露 12 个逻辑处理器，物理核心拓扑不用于本报告的 CPU 换算。
- 内存：31.7 GiB；Windows 11 Home China；WebView2 157.0.4341.60；缩放 200%。
- 桌宠 540×590、控制台 470×780 逻辑像素；角色目标帧率 24 fps。
- 发布 EXE SHA-256：`b5f3243488d41809662e92c91f05aae7daa6a2a12a65f3ad323d8fe2b857ea65`。全程未修改或重新编译应用功能代码。测试脚本和诊断操作均使用独立用户目录，不读取或改写日常设置。
- 每秒采样本次 Rust 进程及其全部后代，自动排除其他应用的 WebView2、测试脚本和采样器。正常启动段预热 15 秒后采样 35 秒；各功能段预热 3 秒后采样 25 秒。函数热点另采样 8 秒，使用 1 ms 的 V8 采样间隔。OS 场景均值不包含函数采样时间。

CPU 是按全部逻辑处理器归一化后的整机百分比，100% 表示全部逻辑处理器占满；例如 3% 在本机约为 0.36 个逻辑核。P95 和峰值来自约 1 秒的采样窗口，无法代表毫秒级瞬时峰值。MiB=1,048,576 字节。

**独占驻留**是本应用当前独占的物理页，可跨进程相加；**提交内存**是私有已提交虚拟内存，不等于全部都在物理 RAM 中；**工作集合计**含进程间及系统共享页，跨进程求和会重复计数，不能视作本软件独占 RAM。这三列不能相加。GPU 进程内存也不等于专用显存；本次没有单独测量显存、电量或 GPU 硬件利用率。

### 热点一：透明命中掩码

[public/pet-hit-region.js](public/pet-hit-region.js#L109) 的 render 每次重画并读取整幅 540×590 RGBA 画布，然后逐像素扫描、创建行矩形数组、JSON 序列化并发送 Rust。单次 ImageData 数据量为 **1.22 MiB**，本次待机约 16.0 次掩码发送／秒、音频同步约 24.1 次／秒，对应约 **19.5～29.2 MiB/s** 的像素数据量级。这是依据尺寸与发送次数计算的量级，不是实测内存带宽；未发送的重复计算会使实际开销更高。getImageData 是最明显的单项采样热点。

JS 分配采样（不是存活内存）：待机 10.9 MiB／8 秒，其中 render 约 9.1 MiB；音频同步 86.7 MiB／8 秒。采样估计可能遗漏或放大短命分配，且不覆盖全部 Canvas／纹理／驱动分配，不能将这些值解释为内存泄漏速度。

### 热点二：音频采样的编码、解码与频繁分配

[native/src/audio.rs](native/src/audio.rs#L65) 以 1024 点块发送 48 kHz 单声道浮点采样，每秒约 46.875 次；有效载荷 192,000 B/s（0.183 MiB/s）。[native/src/main.rs](native/src/main.rs#L461) 将其 Base64 化后经脚本送入网页，[src/audio/native-system.ts](src/audio/native-system.ts#L45) 再使用 atob、Uint8Array.from 和逐字符回调转换，最后传入 AudioWorklet。原生采样线程还为每块新建 Vec。数据总量很小，但跨层包装和短命对象值得优化。

[src/audio/frozen-audio-core.js](src/audio/frozen-audio-core.js#L3) 的 estimate／自相关是次级计算热点；在本次测试信号下小于透明命中计算。[public/native-pcm-worklet.js](public/native-pcm-worklet.js#L4) 的固定环形缓冲仅 64 KiB，原生排队上限 3×4 KiB，它们本身解释不了数百 MiB 的进程内存。AudioWorklet 线程未包含在主页面函数采样中。

### 热点三：图形资源及浏览器常驻内存

当前透明版本预加载 31 张 800×800 PNG（不含停用的场景背景），压缩文件共 0.4 MiB，单份 RGBA 解码理论数据量共 **75.7 MiB**。休闲时页面实际挂载 12 张图，对应单份解码数据约 29.30 MiB；解码缓存、GPU 纹理、合成表面、Canvas 缓存和浏览器运行时另计，不能把 PNG 压缩体积当作运行内存。两倍系统缩放下的原生表面也更大。

[src/character/assetLoader.ts](src/character/assetLoader.ts#L160) 使用 Promise.all 预加载所有表情；[public/pet-hit-region.js](public/pet-hit-region.js#L39) 再缓存多组完整尺寸 Canvas。这里有按实际显示区域裁紧素材、合并静态层和缩减多份图形表面的空间。仅凭 OS 工作集无法精确断言每张纹理占用了哪一块内存，故不把 WebView2 GPU 进程所有内存归因于素材。

## 4. 因果对照：停用命中计算后再恢复

| 同一实例顺序 | CPU 均值 | 独占驻留均值 MiB | 掩码发送／秒 |
| --- | --- | --- | --- |
| baseline_before | 2.64% | 418.0 | 15.9 |
| mask_disabled | 1.34% | 434.2 | 0.3 |
| baseline_after | 2.06% | 435.0 | 16.0 |

A/B/A 仅断开负责 body 子树变化的命中观察器，确认唯一命中该观察器；之后按原参数恢复。没有暂停角色动画、移除素材或改写节拍逻辑。两次正常段均值 2.35%，停用段 1.34%，减少 1.01 个整机 CPU 百分点，约 **42.8%**。对照段都在强制回收后短暂预热，内存差异仍受缓存和分配器保留影响，不能将其直接视作最终可回收空间。

停用观察器后仍保留图片 load、resize 等触发，因此掩码发送不必完全为零；其频率已显著下降。

两次正常段自身也有波动，分别为 2.64% 与 2.06%；停用段相对它们的降幅范围为 34.8%～49.1%。约 43% 是本次短窗口的定位结果，不能直接当作未来正式优化后的保证收益。

锁定整窗本已穿透，但当前实现仍在生成并发送精细掩码；隐藏控制台也只是隐藏原生窗口，未卸载 WebView2 和 React portal，因此不能期待隐藏后内存立即大幅下降。

## 5. 是否存在泄漏

| 时间点（均手动触发 GC） | JS 活堆 MiB | backing storage MiB | DOM 文档／节点／监听器 |
| --- | --- | --- | --- |
| 首次预热后（强制回收） | 2.7 | 8.8 | 2／171／341 |
| 全部功能运行后（强制回收） | 3.5 | 9.3 | 2／175／342 |

执行计时、表情压力、音频后回到待机，JS 活堆从 2.7 增至 3.5 MiB，约增加 0.8 MiB；文档数保持 2。音频停止后的独占驻留从运行音频时 799.2 降至 598.0 MiB，说明相当一部分是可释放或可修剪的运行资源。

当前证据支持“图形／浏览器缓存与频繁临时分配造成高占用”，不足以确认持续泄漏，也不能据此保证没有泄漏。该测试只覆盖数分钟场景；确诊应进行 30～60 分钟相同状态的循环、记录每轮回收后的进程与堆基线，并补充图形资源归属分析。

## 6. 建议优先级

| 优先级 | 建议 | 依据与验收方式 |
| --- | --- | --- |
| P0 | 锁定时停止精细命中更新；解锁前立即刷新一次 | 锁定已整窗穿透，当前仍算掩码；验证锁定／解锁与边缘穿透不倒退 |
| P0 | 保存静态 alpha／各刚性图层 alpha，在 Rust 或统一缓冲中按变换判定光标点，减少整画布 getImageData | A/B/A 已确认是首要 CPU 来源；必须保留半透明边缘、动态配件和内部透明空隙，不能回退到 SetWindowRgn 裁切画面 |
| P1 | 复用掩码矩形和消息缓冲，只在需要时发变化；避免每帧数百数组与 JSON | 降低临时对象和跨层解析；对比 render 采样、GC 与实际 CPU |
| P1 | 同时检查 Rust 侧 JSON 解析、每行 Vec 构建和窗口穿透样式切换 | Rust 内存小但本次 CPU 并非可忽略；用原生采样进一步区分 IPC、解析和系统窗口调用 |
| P1 | 合并不动的素材层，离线裁紧透明边界，按需加载表情 | 保持现有视觉坐标与缩放；测量私有驻留和 GPU 进程内存，不能只看 JS 堆 |
| P2 | PCM 改为可复用二进制消息／共享缓冲，减少 Base64 和逐字符回调 | 有效音频数据仅约 0.183 MiB/s；优化跨层开销但保持采样率与节拍输出 |
| P2 | 控制台隐藏时降低无须显示的刷新；评估延迟创建控制台 | 隐藏不释放 WebView2；保留共享计时、音频和状态，避免重复实例 |
| P3 | 再评估单独降低鼠标轮询频率或重写节拍算法 | estimate 次于掩码；单独降低轮询对整体的收益尚未测量，并可能损害快速进入角色时的交互 |

以上是定位结论与建议，本次没有把诊断停用当作优化交付，也没有改动发布 EXE。每项优化都应在同一台机器、同样缩放与场景下复测，并运行透明穿透、UI 对齐和音频功能回归。
